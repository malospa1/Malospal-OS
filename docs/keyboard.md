# PS/2-клавиатура Malospal OS

USB xHCI и встроенные клавиатуры ноутбуков описаны в [отдельной инструкции](usb-keyboard.md).

Команды теперь можно вводить непосредственно в окне QEMU или VirtualBox.
Это собственный драйвер ядра: контроллер i8042, IRQ1, очередь скан-кодов и
декодер PS/2 set 2. Готовая консоль прошивки или ввод через Windows API в госте
не используются. COM1 остаётся независимым вторым источником ввода.

## Запуск

Запусти `run-kernel.cmd` или подключи `kernel/build/normal/malospal-os.iso` в VirtualBox.
Дождись `[ok] PS/2 input ready (IRQ1, set 2, US)` и `malospal> `, щёлкни внутри
окна машины, набери `help` и нажми Enter. В VirtualBox нужен тип клавиатуры PS/2,
не USB. COM1 можно оставить для дополнительного журнала или выключить.
Обычная USB-клавиатура хоста подходит: эмулятор представляет её гостю как PS/2.

Разрешены те же команды, что через COM1; новая команда `keyboard` показывает
число скан-кодов, декодированных байтов, IRQ1, потерь, ошибок и состояние драйвера.
`info` перечисляет действительно готовые источники ввода.

Поддерживаются:

- Фиксированная английская раскладка US: буквы, верхний ряд цифр и знаки.
- Левый/правый Shift, программный Caps Lock, их совместное действие.
- Enter и Enter цифрового блока, Backspace, Delete как удаление последнего символа.
- Tab как один пробел, Ctrl+U как очистка текущей строки, в том числе отвергнутой.
- Автоповтор печатных клавиш, если повторные make-коды присылает устройство.

В VirtualBox назначенная Host-клавиша обрабатывается самой программой;
для Ctrl+U используй левый Ctrl. В окне Malospal OS Ctrl+C не выключает эмулятор:
закрой его окно или используй Ctrl+C в терминале запуска QEMU.
Escape и неподдерживаемые печатные сочетания с Alt отменяют текущую строку.
Стрелки доступны играм через `keyboard_read_key()`, но игнорируются текстовым
редактором через `keyboard_read()`. Функциональные клавиши, Print Screen и Pause
игнорируются. Нет истории,
позиционного редактирования, Num Lock/цифр цифрового блока, Unicode и русской раскладки.
Индикатор Caps Lock на физической клавиатуре пока не синхронизируется с состоянием Malospal OS.

## Инициализация

Драйвер запускается один раз, после PIC/PIT, при IF=0. Он владеет обоими портами
i8042 (`0x60` и `0x64`); порт мыши и IRQ12 остаются выключенными.
Перед настройкой отключаются интерфейсы и очищается старый выходной буфер.
Обычная загрузка использует `keyboard_init_timed()`: контроллер не сбрасывается
через AA, тест интерфейса AB пропускается ради совместимости с EC ноутбуков.
Трансляция set 2 в set 1 отключается, конфигурация проверяется чтением обратно.
Строгий `keyboard_init()` с AA/AB сохранён и проверяется локальными тестами.

Сканирование клавиатуры останавливается командой F5. Затем выбирается set 2,
набор проверяется запросом, индикаторы сбрасываются, сканирование включается F4.
Для каждого байта команды ожидается ACK; ответ RESEND допускает всего три попытки.
Команды reset CPU/A20 не используются. Параметры сверены с
[описанием i8042 Intel](https://intel.github.io/ecfw-zephyr/reference/kbchost/index.html),
[контроллером QEMU](https://github.com/qemu/qemu/blob/v11.1.0/hw/input/pckbd.c)
и [клавиатурой QEMU](https://github.com/qemu/qemu/blob/v11.1.0/hw/input/ps2.c).

В обычной загрузке ожидание ограничено 50 тиками PIT (номинально 500 мс)
и миллионом опросов. Во время ожидания разрешается доставка таймера, IRQ1 остаётся
закрытым. Это время по доставленным тикам, а не гарантированное настенное время.
Очистка буфера ограничена 256 чтениями. Диагностика `[ps2]` показывает этап,
последние status и reply, чтобы различить отсутствие порта и отказ команды.
Ошибка оставляет IRQ1 закрытым, а доступный COM1 продолжает работать.
Повторная настройка и горячее переподключение пока не поддерживаются.

## Ввод и ошибки

IRQ1 сохраняет сырые скан-коды в кольцо на 256 ячеек (полезно 255).
Обработчик не рисует, не выполняет команды и не выделяет память. Данные AUX
не попадают в декодер; ошибки чётности и таймаута отменяют очередь.
Обработка IRQ ограничена 256 чтениями; неосвобождающийся буфер считается отказом,
и IRQ1 маскируется. Учёт ведётся на одном CPU, операции чтения сохраняют IF.

Декодирование происходит при чтении в основном цикле. Оно различает make/break,
префиксы E0/F0 и полную последовательность Pause с E1. Искусственный Shift в
Print Screen не меняет настоящий Shift. Caps Lock переключается только при
первом нажатии, а не при повторах удерживаемой клавиши.

Потеря, некорректная последовательность или неожиданный ответ устройства
сбрасывают состояние декодера и отменяют незавершённую команду. Для восстановления
отпусти модификаторы и нажми Enter или Ctrl+U. Счётчик потерь учитывает только
известные отброшенные байты, не все возможные аппаратные потери.

Консоль по очереди проверяет COM1, PS/2 и USB. При переключении устройства посреди
строки она отменяет строку, а не склеивает части команд. Полные команды можно
чередовать между PS/2, USB и COM1. При отказе одного работает другое готовое устройство;
при отказе последнего во время работы выводится диагностика и ядро останавливается.
Если все отсутствуют уже при загрузке, экран показывает сообщение готовности
без ввода, а таймер продолжает будить CPU.

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 unit
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 keyboard
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 keyboard -Uefi -Memory 256
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 check
```

Локальные проверки включают настоящий декодер (в том числе 100000 случайных
байтов) и драйвер на подставных портах. Проверяются задержки, RESEND, неверные
ACK/набор/конфигурация, самотесты, отсутствующий и зависший контроллер, таймаут,
чётность, IRQ1, оборачивание и переполнение очереди, AUX и сохранение IF.

QEMU получает настоящие события клавиш через
[QMP input-send-event](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html#command-input-send-event).
Тест не подменяет очередь или декодер в ядре. BIOS/128 МиБ и UEFI/256 МиБ
проверяют команды, Shift/Caps/Ctrl, редактирование, E0/E1, границы строк,
смешивание источников, рост тиков, IRQ1, отсутствие потерь и утечек страниц.
Без COM1 выполнение `echo Malospal` проверяется по настоящим пикселям экрана.
Без i8042 проверяется запасной ввод через COM1.

Полный набор: 30 локальных групп и 63 запуска QEMU. Журналы и снимки:
`kernel/build/normal/keyboard-*`; текущий общий журнал: `kernel/build/check-usb.log`.

2026-10-16 дополнительно проверен VirtualBox 7.2.16: BIOS, один CPU, 1024 МиБ,
VBoxVGA, PS/2 и журнал COM1 Raw File. Работают команды, Backspace, Ctrl+U,
Shift и Caps Lock; счётчики потерь и ошибок равны нулю. Снимок:
`kernel/build/normal/keyboard-virtualbox.png`. Эта проверка не входит в 63 запуска
QEMU. Исправлен также остаточный байт COM1, отменявший первую строку после
загрузки; [подробности](console.md#внутреннее-устройство).

Проверки эмуляторов не доказывают работу на физическом компьютере. Пока нет
поиска PS/2-контроллера через ACPI, мыши, SMP и восстановления после переподключения.
USB legacy handoff для xHCI и USB boot-HID теперь реализованы отдельно;
EHCI legacy и I²C-клавиатуры пока не поддерживаются.
