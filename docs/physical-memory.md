# Физическая память Malospal OS

Ядро теперь умеет выделять и освобождать отдельные физические страницы
размером 4096 байт. За это отвечает PMM (Physical Memory Manager).
Он уже выдаёт страницы для собственных таблиц виртуальной памяти и станет
основой для динамических стеков и кучи ядра,
но ещё не аналог `malloc`: блоки произвольного размера пока не выдаются.

## Запуск проверки

Из корня репозитория в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 memory
```

Тест работает только внутри QEMU. Он выделяет две страницы, проверяет запись
по всему их объёму, освобождение и повторное использование. Затем занимает
все доступные страницы гостя, записывает контрольные значения в начало и конец
каждой, проверяет отказ при исчерпании и возвращает страницы обратно.
Ошибочное освобождение не должно менять состояние распределителя.

Успешный результат содержит:

```text
[test] PMM allocation, writes, reuse and invalid frees: OK
[test] PMM exhausted and restored ... pages: OK
MALOSPAL_PMM_TEST_OK
PASS: memory test, BIOS, 128 MiB.
```

UEFI и другой объём памяти:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 memory -Memory 256 -Uefi
```

Только локальные проверки на искусственных картах, без QEMU:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 unit
```

Команда `check` объединяет 30 групп локальных тестов и 63 запуска QEMU.
Образ проверки памяти находится в `kernel/build/memory/malospal-os.iso`, журналы
в `kernel/build/memory/memory-*.log`. Обычный `run-kernel.cmd` не исчерпывает
память: он инициализирует PMM, печатает статистику и переходит в ожидание.

## Какие страницы доступны

`boot/limine.c` копирует карту памяти и переводит типы областей в собственный
формат `boot_info`. PMM рассматривает только `BOOT_MEMORY_USABLE`.
Области ядра и модулей, загрузчика, ACPI, framebuffer, плохая и зарезервированная
память недоступны для выдачи. Неизвестный тип также не становится доступным.

Начало каждой доступной области округляется вверх до границы страницы,
конец вниз. Физическая страница 0 исключается. Проверяются переполнения,
порядок областей и пересечения доступной памяти с любой другой областью.
Пересечения между двумя недоступными областями допустимы.
Карта больше 512 записей отклоняется, а не молча обрезается.

У каждой целой доступной страницы есть один бит состояния. Нумерация битов
плотная: большие разрывы между физическими адресами не увеличивают размер
карты. Для `N` учитываемых страниц нужно `ceil(N / 8)` байт, округлённых
до целых страниц. Место для карты берётся из подходящей доступной области,
немедленно резервируется и никогда не выдаётся вызывающему коду.

Например, в журнале проверки BIOS с 128 МиБ RAM:

```text
PMM total=32353 free=32279 allocated=73 metadata=1
```

`total` включает целые доступные страницы после исключения страницы 0;
`metadata` заняты самой битовой картой, `allocated` выданы вызывающему коду,
`free` свободны. Всегда должно выполняться:
`total = free + allocated + metadata`. Это не полный объём установленной RAM.
Теперь `allocated` уже после загрузки ненулевой: в нём учтены страницы
собственных таблиц VMM. Тест памяти возвращает счётчики к исходным значениям,
не освобождая действующие таблицы.

## Интерфейс

Объявления находятся в `kernel/include/malospal/pmm.h`:

```c
bool pmm_init(const struct boot_info *info);
bool pmm_alloc_page(uint64_t *physical_address);
bool pmm_free_page(uint64_t physical_address);
struct pmm_stats pmm_get_stats(void);
```

`pmm_init` успешно выполняется только один раз. Повторная инициализация
отклоняется, чтобы не потерять уже выданные страницы. При неудачной
инициализации распределитель остаётся недоступен, статистика возвращает нули.

`pmm_alloc_page` возвращает `false`, если памяти нет, аргумент отсутствует
или PMM ещё не готов. При отказе выходной адрес не меняется. При успехе
выдаётся физический адрес страницы; содержимое не обнуляется.

`pmm_free_page` принимает только выровненный адрес сейчас выданной страницы.
Нулевой, служебный, зарезервированный, свободный и посторонний адреса
отклоняются. Освобождение не снимает виртуальное отображение и не стирает
данные. Вызывающий код обязан прекратить использование страницы до её возврата.
Проверка битовой карты не различает старую ссылку и новую выдачу того же адреса:
это не защита от всех случаев use-after-free и не учёт владельцев процессов.

Физический адрес нельзя просто разыменовать. Используется HHDM:
виртуальный адрес доступной страницы равен физическому плюс сохранённое
смещение прямого отображения. Это не универсальный способ доступа к устройствам
или любому зарезервированному адресу. Начальное отображение доступной памяти
и размещение таблиц загрузчика описаны в
[протоколе Limine v8.7.0](https://github.com/limine-bootloader/limine/blob/v8.7.0/PROTOCOL.md#entry-memory-layout).
После запуска [VMM](virtual-memory.md) это отображение поддерживается уже
таблицами ядра и охватывает целые страницы доступной RAM, кроме
нулевой страницы. Отдельно отображается зарезервированный framebuffer, который
не становится доступной памятью PMM. Код ядра не получает доступного для записи прямого алиаса.

## Проверенное и ограничения

Полный набор содержит 30 групп локальных тестов и 63 проверки QEMU.
Тест исчерпания и возврата проверяет BIOS/32 МиБ, BIOS/128 МиБ и UEFI/256 МиБ;
актуальное число возвращённых страниц печатается в `build/memory/memory-*.log`.
Эти числа могут меняться при изменении размера ядра и прошивки.

Локальные тесты используют настоящий код PMM с искусственными картами:
нулевая страница, разрывы, адреса на 1 ТиБ, неполные страницы, недопустимые
карты, все типы резервов, 512 областей, карта размером в две страницы,
полное исчерпание и 20000 смешанных операций с проверкой уникальности адресов.
Сборка этих тестов включает UBSan с аварийным завершением при обнаружении
неопределённого поведения. Высокие адреса проверяются арифметически,
реальный компьютер с 1 ТиБ RAM не требуется.

Пока нет многопроцессорных блокировок и вызовов из обработчиков прерываний:
PMM используется одним CPU при отключённых маскируемых прерываниях.
После включения таймера вызывающий код должен сохранять и выключать IF через
`arch_irq_save()`, затем восстанавливать его через `arch_irq_restore()`.
Сам обработчик таймера не обращается к PMM/VMM.
Нет выделения непрерывных блоков из нескольких страниц, DMA-зон, NUMA,
крупных страниц, кучи и пользовательских адресных пространств.
ACPI и память загрузчика остаются зарезервированными. Таблицы страниц
уже принадлежат ядру; PMM учитывает их как выданные страницы.
