# Прерывания и таймер Malospal OS

Ядро умеет обрабатывать аппаратные сигналы и продолжать прерванный код.
Первое устройство с таким обработчиком: периодический таймер.
Пока поддерживается один процессор, только режим ядра. Автотесты используют
QEMU q35; обычная загрузка также проверена в VirtualBox.

## Запуск

Из корня репозитория:

```powershell
.\run-kernel.cmd
```

После сообщений о памяти появится:

```text
[ok] PIC IRQs and PIT timer ready (~100 Hz)
[ok] Serial input ready (COM1 IRQ4)
[ok] PS/2 input ready (IRQ1, set 2, US)
Malospal OS console
malospal> ticks
TIMER ticks=100 nominal_hz=100
malospal>
```

Значение зависит от момента команды. Таймер продолжает работать во время ввода,
но не печатает сообщения сам. Повторный `ticks` показывает новый счётчик.
Между событиями консоль использует `hlt`; переключения задач пока нет.
[Команды и ввод](console.md).

Отдельный тест, который сам завершает QEMU:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 timer
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 timer -Uefi -Memory 256
```

Ожидается `MALOSPAL_TIMER_TEST_OK` и `PASS`. Журналы находятся в
`kernel/build/timer/timer-*.log`; обычный образ тестами не заменяется.

## Устройство

Два совместимых с 8259A контроллера PIC получают векторы 32..47, вне диапазона
исключений процессора. После настройки PIT открыта IRQ0, обычное ядро затем
открывает IRQ4 для COM1 и IRQ1 для PS/2, если устройства доступны.
Остальные линии, включая каскад IRQ2 и мышь IRQ12, замаскированы.
Тест таймера по-прежнему открывает только IRQ0. Внутренний драйвер умеет
управлять масками и автоматически открывать каскад при включении линии slave.
Он требует отключённых IRQ. Реальные прерывания без драйвера маскируются.

Обслуживание заканчивается подтверждением EOI. Для slave сначала подтверждается
slave, затем master. Для ложного IRQ7 подтверждение не отправляется; для ложного
IRQ15 оно требуется только master. Различение выполняется по биту ISR.
Последовательность основана на [документации Intel 8259A](https://pccomponents.com/datasheets/INTEL-P8259A2.pdf).

PIT использует канал 0, двоичный режим 2, делитель 11932 и номинальную входную
частоту 1193182 Гц. Получается приблизительно 100 IRQ в секунду.
Формат команд и режим проверены по [документации Intel 8254](https://www.cs.usfca.edu/~cruse/cs210s07/8254.pdf).
Каналы 1/2 и динамическая смена частоты пока не используются.

Ассемблер сохраняет 15 регистров общего назначения, очищает DF для C-кода
и выравнивает стек для вызова. C-диспетчер обслуживает IRQ и подтверждает его
контроллеру. Затем регистры восстанавливаются, а `iretq` возвращает RIP,
CS, RFLAGS, RSP и SS. Входы IDT имеют тип interrupt gate, поэтому вложенные
маскируемые IRQ во время обработчика выключены. DF прерванного кода восстанавливается.
Исключения по-прежнему печатают диагностику и останавливают ядро.

## Интерфейсы

| Функция | Контракт |
| --- | --- |
| `arch_irqs_init()` | Один раз после установки IDT, при IF=0; все линии закрыты |
| `timer_init()` | Один раз после PIC, при IF=0; настраивает PIT и открывает IRQ0, IF не меняет |
| `timer_ticks()` | Число доставленных тиков; 64-битное чтение на одном CPU |
| `timer_wait_ticks(n)` | Требует готового таймера и IF=1, принимает `n <= INT64_MAX`, сохраняет IF; 0 возвращается сразу |
| `arch_irq_save()` | Сохраняет флаги, выключает маскируемые IRQ |
| `arch_irq_restore(flags)` | Восстанавливает только IF, допускает вложенные критические секции |
| `arch_irq_wait()` | Внутренняя операция ожидания: вход и выход с IF=0, между ними `sti; hlt; cli` |

Ожидание проверяет счётчик с IF=0. Соседние `sti; hlt` используют отсрочку
доставки маскируемого прерывания после STI, исключая засыпание между проверкой
условия и разрешением IRQ. Это поведение определено в
[Intel SDM, STI и HLT](https://cdrdv2-public.intel.com/782156/325383-sdm-vol-2abcd.pdf).
После пробуждения условие проверяется повторно. Неверный контекст ожидания
возвращает `false`; отсутствующий или сломанный таймер во время ожидания
пока не обнаруживается самим ядром. В тестах зависание ограничено внешним
таймаутом 60 секунд.

После включения таймера PMM/VMM сохраняют прежний контракт. В обычном коде
операции с памятью оборачиваются в `arch_irq_save()` / `arch_irq_restore()`.
Обработчик IRQ0 только меняет счётчик; не печатает, не выделяет память и не ждёт.
Сохранение SSE/x87, переключение пользовательских стеков и `swapgs` пока не нужны:
ядро собирается без SSE/MMX и не выполняет вычислений с плавающей точкой.

## Проверки и ограничения

Полный прогон включает 63 запуска QEMU и 30 локальных групп тестов:
7 для PMM, по 1 для PIC, UART и редактора строки, 2 для экранного вывода,
1 для декодера PS/2, 14 сценариев i8042, 1 для USB HID и по 1 для логики Змейки и слотов.
USB xHCI опрашивается основным циклом, без отдельного IRQ; PIT будит CPU для опроса.
Таймер отдельно проверен
в BIOS/32 МиБ, BIOS/128 МиБ и UEFI/256 МиБ. Обычный образ проверяется по двум
ответам команды `ticks` с растущим счётчиком,
загрузочный тест тоже должен получить несколько настоящих IRQ.

Тест таймера проверяет маски PIC и режим PIT, ложные векторы, 16 реальных
пробуждений с контрольными значениями всех GPR, RSP, арифметических флагов,
IF/DF и данных стека. Используются два выравнивания прерванного стека.
Дополнительно проверяются 100 последовательных ожиданий, вложенное сохранение
IF, отсутствие активных битов ISR после возврата и неизменность учёта PMM/VMM.
Локальный тест исполняет настоящий `pic.c` с подставными портами и проверяет
точную последовательность инициализации, маски, каскад, ложные IRQ и порядок EOI.
Программные `int` в тесте ложных векторов не заменяют проверку электрического
сигнала реального устройства; аппаратный источник здесь только PIT.

Счётчик тиков не является часами реального времени. При долгом запрете IRQ
события могут объединяться, а паузы эмулятора влияют на наблюдаемое время.
Нет ACPI/APIC, HPET, калибровки часов, SMP, очередей таймеров или планировщика.
Дополнительно проверены COM1 IRQ4 и PS/2 IRQ1. Экранный драйвер IRQ не использует;
другие источники прерываний и реальный компьютер пока не проверены.

Файлы: `src/arch/x86_64/{exceptions.S,interrupts.c,pic.c,pit.c,cpu.c}`,
`include/malospal/{arch.h,timer.h}` и `tests/{pic_host.c,timer_kernel.c,timer_registers.S}`
в каталоге `kernel/`.
