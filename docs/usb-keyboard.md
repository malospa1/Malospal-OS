# USB-клавиатуры и встроенные клавиатуры ноутбуков

Malospal OS принимает ввод от USB boot-HID клавиатур через собственный драйвер xHCI.
Этот ввод работает в консоли, Змейке и слот-машине, в том числе без PS/2 и COM1.
Обычный запуск QEMU и настройки VirtualBox по-прежнему используют PS/2.

## Как обновить уже загружающуюся флешку

Из корня репозитория выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 build
```

Готовые файлы находятся в `.\kernel\build\normal\usb-uefi`.
Скопируй **содержимое** этой папки в корень своей существующей FAT32-флешки
с заменой одноимённых файлов. Структура в корне флешки:

```text
EFI/BOOT/BOOTX64.EFI
kernel.elf
limine.conf
limine-license.txt
pcg-license.txt
pcg-info.txt
authors.txt
third-party.txt
SHA256SUMS
```

Если флешка уже загружала эту Malospal OS, для изменения драйвера достаточно заменить
в её корне `kernel.elf` файлом `kernel/build/normal/kernel.elf`.
Сборщик не выбирает диски, не форматирует и не записывает физические носители.
`malospal-os.iso` остаётся CD/DVD-образом, не гибридным образом для побайтовой записи на USB.
Этот набор файлов рассчитан на UEFI x86-64 и отключённый Secure Boot, как при
предыдущем успешном запуске; сам загрузчик не подписан. BIOS-загрузка флешки
этой раскладкой не настраивается.

Подключи клавиатуру непосредственно к компьютеру **до включения Malospal OS**.
Для первой проверки убери USB-хабы, док-станции и переходники с хабом.
После загрузки ожидаются строки:

```text
[usb] xHCI ready=1 keyboards=1 unsupported=0 failed=0
[ok] USB keyboard input ready (xHCI, boot HID, US)
malospal>
```

Предупреждение `PS/2 keyboard unavailable` само по себе не мешает USB-вводу.
Введи `help`, затем `keyboard`, `snake` или `slots`. Раскладка US; поддерживаются
Shift, программные Caps/Num Lock, Ctrl+U, Enter, Backspace, Delete, стрелки и
автоповтор. Светодиоды USB-клавиатуры пока не синхронизируются.

## Ноутбуки и границы поддержки

Встроенная клавиатура — не отдельный универсальный протокол. Поддержаны:

- PS/2 / i8042, в том числе реализованный встроенным контроллером EC.
  Обычная загрузка использует ожидание ответов по PIT и не повторяет сброс
  контроллера через AA и тест интерфейса AB. Выбор set 2, ACK и конфигурация всё равно проверяются.
- USB boot-HID на непосредственно подключённом порту xHCI.

Пока отсутствуют HID-over-I²C, SPI, USB-хабы, EHCI/OHCI/UHCI и Bluetooth.
Некоторые игровые NKRO-клавиатуры не предлагают boot-HID интерфейс.
На старых Intel-чипсетах порты могут быть направлены в EHCI: автоматического
переключения маршрутизации между EHCI и xHCI сейчас нет.
Если устройство не подошло, нужна модель ноутбука/платы и строки `[usb]`/`[ps2]`
с экрана. Это позволит определить следующий драйвер или аппаратную особенность.

Драйвер перечисляет устройства только при загрузке. При отключении клавиатуры
её незавершённый ввод отменяется; другое готовое устройство продолжает работать.
Для подключения или восстановления USB-клавиатуры перезагрузи Malospal OS.
Если последний источник ввода отказал, ядро останавливается с диагностикой.

## Устройство реализации

- `pci.c`: конфигурационный механизм PCI #1, сегмент 0, назначенные прошивкой
  адреса BAR. До четырёх xHCI-контроллеров, до восьми клавиатур на каждом.
- `paging.c`: отдельное окно MMIO `0xffffc00100000000`, UC/RW/NX. Нельзя отображать
  туда RAM, ядро, framebuffer или области прошивки. Обычный RAM-интерфейс VMM
  не меняет эти отображения. PAT3 должен содержать UC.
- `usb/xhci.c`: передача владения BIOS→OS, остановка и сброс xHCI, DCBAA,
  scratchpad, командное кольцо, кольцо событий, control и interrupt endpoints.
  Поддержаны контексты 32/64 байта, страницы 4 КиБ, до 64 scratchpad-страниц,
  регистры в первых 64 КиБ BAR и устройства USB 2 low/full/high speed на root ports.
- `usb/hid.c`: проверка дескрипторов первой конфигурации (до 4096 байт), выбор
  первого boot keyboard интерфейса alt 0, SET_PROTOCOL(Boot), восьмибайтовые
  отчёты, отпускания, модификаторы, повтор и отмена ввода при rollover.
- `core/input.c`: справедливый опрос COM1, PS/2 и USB. У каждой USB-клавиатуры
  отдельный ID источника; консоль не склеивает команды от разных устройств.

Кольца и буферы берутся из PMM и остаются доступными DMA. У клавиатуры восемь
одновременно выставленных запросов, поэтому опрос основным циклом не ограничивает
её одним отчётом за тик. IRQ от xHCI не включаются; PIT будит спящий процессор.
При чтении ввода нет выделений памяти, блокирующих ожиданий или вывода на экран.
Один опрос контроллера обрабатывает не больше 64 событий.
Ожидания при инициализации ограничены доставленными тиками PIT.

Неудачная настройка устройства освобождает его страницы только после успешного
Disable Slot. При отказе контроллера bus mastering отключается; если остановка
не подтверждена, DMA-страницы удерживаются до перезагрузки. После рабочего
отключения устройства его ресурсы тоже удерживаются, повторного перечисления нет.
Контроллер без 64-битного DMA отвергает выделение выше 4 ГиБ; специального пула
низкой памяти пока нет. IOMMU, SMP и USB-прерывания пока не реализованы.

Описание регистров сверялось с [Intel xHCI 1.2c](https://cdrdv2.intel.com/v1/dl/getContent/868295),
формат клавиш — с [USB HID 1.11](https://www.usb.org/sites/default/files/hid1_11.pdf).
Поведение встроенных контроллеров описано в
[документации Intel EC](https://intel.github.io/ecfw-zephyr/reference/kbchost/index.html).

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 unit
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 usb
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 usb -Uefi -Memory 256
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 check
```

USB-сценарии запускают обычное ядро с `qemu-xhci`, `usb-kbd` и `i8042=off`.
Проверяются BIOS/UEFI, команды, модификаторы, переходы колец через границу,
управление обеими играми, память, отключение устройства и резервный COM1.
Без COM1 выполнение команды и управление слотами проверяются по пикселям.
Отдельно проверяются пустой контроллер и два контроллера с мышью, хабом и
клавиатурой: неподдержанные устройства не мешают подходящей клавиатуре.
Локальные тесты проверяют HID rollover/повтор/отпускание и испорченные дескрипторы,
медленный EC, отсутствующие self-test команды, таймаут и диагностику PS/2.
VMM-тесты проверяют UC/NX, запрет RAM-алиасов и возврат таблиц после MMIO.

Общий набор: 30 локальных групп, 63 запуска QEMU. Журнал: `kernel/build/check-usb.log`.
USB-журналы и снимки: `kernel/build/normal/usb-*`.
Загрузка старого ядра на физическом компьютере подтверждена фотографией пользователя;
работоспособность новых USB/EC изменений на том компьютере ещё нужно проверить.
