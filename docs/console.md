# Командная консоль Malospal OS

Консоль выполняет встроенные команды самого ядра. Ввод идёт от PS/2-клавиатуры,
USB boot-HID через xHCI и COM1, вывод дублируется на экран и COM1. Windows API внутри гостевой
системы не используется. Это ещё не оболочка
для запуска файлов и программ: процессов и файловой системы пока нет.

## Запуск и команды

Из корня репозитория:

```powershell
.\run-kernel.cmd
```

Дождись `malospal> `, переключись на английскую раскладку и введи `help`.
Команды вводятся прямо в графическом окне QEMU или в терминале запуска.
`run -Headless` запускает только терминал. PS/2 использует фиксированную раскладку US.

| Команда | Результат |
| --- | --- |
| `help` | Список команд |
| `info` | Версия ядра, архитектура и доступные подсистемы |
| `mem` | Число физических страниц, выделенные таблицы и корень VMM |
| `ticks` | Счётчик доставленных тиков и номинальная частота |
| `serial` | Принятые байты, очередь, потери, ошибки и число IRQ4 |
| `keyboard` | Скан-коды, декодированные байты, очередь, потери, ошибки и IRQ1 |
| `echo hello` | Печать текста |
| `snake` | Змейка на экране |
| `slots` | Слот-машина с очками за совпадения |
| `halt` | Остановка ядра с отключением маскируемых прерываний |

После `halt` QEMU остаётся открыт: закрой окно QEMU или нажми Ctrl+C в терминале,
чтобы завершить эмулятор.
Ctrl+C работает и во время обычного ожидания ввода. При вопросе Windows о
завершении командного файла ответь `Y`.

Backspace и байт DEL удаляют последний символ, Ctrl+U очищает строку.
Enter принимает CR, LF или CRLF без двойного выполнения. Tab становится одним
пробелом. Команды чувствительны к регистру, начальные и конечные пробелы у команд
без аргументов разрешены. Аргументы пока принимает только `echo`.

Предел строки: 127 ASCII-символов. Более длинная строка не выполняется даже
частично. Неподдерживаемые управляющие байты, Escape и не-ASCII ввод также
отменяют строку до следующего Enter или Ctrl+U. Истории, стрелок, автодополнения
и Unicode пока нет. Счётчик `ticks` не является точными часами реального времени.

Одну строку вводи из одного устройства: переключение между PS/2, USB и COM1 посреди
команды отменяет строку. Enter завершает её отмену, Ctrl+U позволяет начать заново.
Для клавиатуры доступны Shift и Caps Lock; [клавиши и ограничения](keyboard.md).
Игры временно занимают экран и основной цикл; Esc возвращает текст консоли.
[Управление Змейкой](game.md), [управление слот-машиной](slots.md).

## Запуск на Windows

При проверке QEMU 11.1.0 стандартный ввод терял символы из быстро переданного
пакета. Поэтому интерактивный `run` на Windows использует `tools/terminal.py`:
он читает клавиши без локального эха, а данные передаёт COM1 по локальному TCP.
Сокет слушает только `127.0.0.1` на автоматически выбранном порту; после выхода
он закрывается вместе с запущенным экземпляром QEMU. Гостевая сеть отключена.
Все команды по-прежнему разбираются и выполняются в ядре.

Бэкенд сокета предусмотрен [QEMU](https://www.qemu.org/docs/master/system/qemu-manpage.html).
Подробность обработки входного потока видна в
[исходниках Windows stdio](https://raw.githubusercontent.com/qemu/qemu/v10.1.0/chardev/char-win-stdio.c).
На других ОС и при перенаправленном stdin остаётся обычный stdio-путь;
быструю вставку через перенаправленный stdin Windows не следует считать надёжной.
Для автоматических проверок используй `console`, а для ручного ввода обычный `run`.

## Первый запуск в VirtualBox

Перед пересборкой выключи машину, не сохраняя её состояние. Из корня репозитория выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 build
```

Подключи `.\kernel\build\normal\malospal-os.iso` как виртуальный CD/DVD.
Выбери Other/Unknown (64-bit), один процессор, включённый PAE/NX и BIOS
(EFI выключен). Диск для установки не требуется. Для первого запуска достаточно
256 МиБ RAM; фактически загрузка ниже проверена с 1024 МиБ.

Сообщения теперь видны прямо в окне VirtualBox. Для дополнительного журнала
в настройках последовательного порта 1 включи COM1: адрес `0x3f8`, IRQ `4`,
режим Raw File, путь `.\kernel\build\normal\virtualbox-serial.log`.
Этот режим сохраняет вывод UART в файл на хосте, как описано в
[руководстве VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/EN-VBOX-7-2-USER.pdf).
После запуска прочитай журнал:

```powershell
Get-Content .\kernel\build\normal\virtualbox-serial.log -Raw
```

Ожидаются `MALOSPAL_KERNEL_OK`, сообщения готовности PIC/PIT, COM1 и PS/2, затем `malospal> `.
Экран показывает тот же вывод. Если COM1 выключен, ядро всё равно загружается,
и принимает команды с PS/2-клавиатуры окна. Щёлкни внутри машины и введи `help`.
Только если недоступны все источники ввода, появляется
`Kernel ready. No input device; screen output only.` USB xHCI поддержан отдельно;
эта конфигурация VirtualBox продолжает использовать PS/2.
Raw File предназначен только для чтения вывода, ввод команд через него не работает.
Команды в VirtualBox вводятся через PS/2, независимо от журнала Raw File.

На VirtualBox 7.2.16 под Windows проверены BIOS-загрузка и команды с PS/2:
`info`, `help`, `echo`, `serial`, `keyboard`, `ticks`, Backspace, Ctrl+U, Shift и
Caps Lock. Конфигурация: один CPU, 1024 МиБ RAM и VBoxVGA. Снимок
`kernel/build/normal/keyboard-virtualbox.png` показывает результаты в 1024x768x32;
журнал COM1 содержит тот же вывод. После очистки приёмника COM1 первая команда
успешно выполнена в двух чистых загрузках. UEFI и интерактивный обмен COM1 в
VirtualBox пока не проверены. Выключать машину нужно через «Закрыть → Выключить машину»;
обработки кнопки питания ACPI в ядре пока нет.

## Внутреннее устройство

UART настроен на 115200, 8N1. После GDT/IDT, памяти и PIC/PIT включаются
приёмные прерывания COM1 на IRQ4: готовые данные, таймаут FIFO и ошибки линии.
Передающий IRQ не используется. Приём начинается после сброса FIFO и чтения
остаточных байтов до очистки LSR.DR, поэтому вводить команды нужно после
появления приглашения. Опустошение приёмника ограничено 4096 чтениями; если он
остаётся занят, ввод COM1 не включается, а PS/2 остаётся доступна.
Формат регистров сверялся с
[документацией PC16550D](https://media.digikey.com/pdf/Data%20Sheets/Texas%20Instruments%20PDFs/PC16550D.pdf).

Ранняя проверка COM1 передаёт байт через внутреннюю петлю UART. Перед чтением
она ждёт одновременно готовности принятого байта (LSR.DR) и завершения передачи
(LSR.TEMT), затем отключает петлю и очищает FIFO. В VirtualBox ответ приходит
асинхронно; немедленное чтение давало ложный отказ и остановку ядра, а выход
из петли до завершения передачи мог терять первые символы журнала. Ожидание
ограничено миллионом опросов, ошибки линии и неверный ответ считаются отказом.
Поведение петли видно в
[исходниках UART VirtualBox](https://raw.githubusercontent.com/mirror/vbox/master/src/VBox/Devices/Serial/UartCore.cpp).

При проверке VirtualBox одного сброса FIFO оказалось недостаточно: после
самопроверки оставался признак DR, и первое чтение возвращало нулевой байт.
Он ошибочно попадал в консоль и отменял первую команду с PS/2. Дополнительное
опустошение приёмника перед включением IRQ4 устраняет этот случай; остаточные
байты до начала приёма не учитываются как пользовательский ввод.

Драйвер читает UART и складывает байты в кольцевой буфер: 1024 ячейки,
полезная ёмкость 1023 байта. Обработчик не печатает и не выполняет команды.
Чтение LSR в передающем коде также обслуживает приём, чтобы не потерять
ошибки, сбрасываемые чтением этого регистра. Общая очередь изменяется при IF=0
на одном CPU. `serial_read()` и снимок статистики сохраняют состояние IF.

При переполнении или ошибке драйвер отбрасывает накопленную очередь и передаёт
событие потери раньше оставшихся байтов. Консоль отменяет текущую строку,
поэтому усечённая команда не исполняется. `dropped` считает известные отброшенные
байты, но не может узнать точное число байтов, потерянных аппаратно.
После 4096 неустранённых причин IRQ за один вызов UART отключается; консоль
сообщает о неисправности. Если PS/2 готова, консоль продолжает работать с ней;
если источников ввода больше нет, ядро останавливается. Неограниченного цикла внутри IRQ нет.

Когда очередь пуста, консоль проверяет её с IF=0 и ждёт через `sti; hlt; cli`,
не оставляя промежутка для потерянного пробуждения. Команды выполняются при
разрешённых IRQ. `mem` снимает короткий согласованный снимок при IF=0, затем
печатает уже с восстановленным состоянием прерываний. Кучу консоль не использует.

Редактор `src/core/line.c` не зависит от устройства. `core/console.c` по очереди
читает PS/2, USB и COM1 через `core/input.c` и разбирает команды. UART находится в `arch/x86_64/serial.c`,
PS/2 в `keyboard.c` и `ps2_decode.c`, маршрутизация IRQ1/IRQ4 в `interrupts.c`.
Потеря байтов отменяет строку. При отказе одного устройства доступное второе
продолжает обслуживать консоль.

## Проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 console
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 console -Memory 256 -Uefi
powershell -NoProfile -ExecutionPolicy Bypass -File .\kernel\build.ps1 check
```

`console` собирает обычный образ и общается с ним через настоящий COM1.
Проверяются все команды, ошибки и аргументы, рост тиков, неизменность статистики
памяти, CR/LF/CRLF, Backspace/DEL, Ctrl+U, предельная и слишком длинная строки,
неверные байты, восстановление ввода, вставка 80 команд и `halt`.
За прогон передаётся 1130 байт; проверяется работа IRQ4 и отсутствие потерь.
Служебных тестовых команд в ядре нет.

Полный набор включает 63 запуска QEMU и 30 локальных групп. Консоль проверяется
в BIOS с 32/128 МиБ и UEFI с 256 МиБ. Отдельно проверен интерактивный Windows-запуск:
Backspace, Ctrl+U, вставка 20 команд и завершение без оставшегося QEMU.
После добавления окна отдельно проверены команды `info`, `ticks`, `echo`, `halt`
и закрытие окна: разрыв COM1 при нормальном выходе QEMU не считается ошибкой;
если соединение потеряно, а QEMU не завершился за 5 секунд, запуск сообщает сбой.
Локальные тесты с UBSan проверяют редактор на 100000 псевдослучайных байтах,
границы и отмену строк, а драйвер UART на подставных портах: оборачивание очереди,
переполнение, ошибки, таймаут приёма, сохранение IF и зависшее устройство.
После исправления проверки COM1 добавлены сценарии задержанного ответа и
завершения передачи, неверного ответа, ошибки линии, отсутствующего порта и
таймаута. Проверяются также остаточный DR после сброса FIFO, старые байты и
ограничение очистки зависшего приёмника. Дополнительно проверяются RGB24/RGB32, пиксели экрана QEMU, прокрутка,
загрузка без COM1 и без видеоустройства. [Подробнее об экране](screen.md).

Журналы: `kernel/build/normal/console-*.log`; отдельная диагностика запуска QEMU:
`console-*-qemu.log`. Тест ограничивает ожидание подключения 60 секундами и обмен
с подключённым ядром ещё 60 секундами, затем закрывает только свой эмулятор.
Дополнительная команда `keyboard` проверяет PS/2-ввод и работу без COM1;
сценарии и снимки описаны в [документации клавиатуры](keyboard.md).
USB HID проверяется отдельно командой `usb`, включая ввод без PS/2 и COM1 и отключение устройства.
[Обновление флешки и границы поддержки](usb-keyboard.md).
Произвольно большие вставки, реальный UART, физический ввод PS/2/USB и SMP не проверены.
