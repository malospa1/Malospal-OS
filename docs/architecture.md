# Собственное ядро Malospal OS: архитектура и развитие

Цель: постепенно получить небольшую операционную систему со своим ядром,
драйверами и приложениями. Основа написана на C и ассемблере x86-64.
Linux и Buildroot не участвуют в текущей сборке.

## Текущая загрузка

```text
BIOS / UEFI (QEMU); BIOS (VirtualBox)
        |
    Limine                         сторонний загрузчик
        |
    _start                         ассемблерный код ядра: cli, cld, стек 64 КиБ
        |
    kernel_main                    C-код ядра
        |
    COM1 -> свои GDT/TSS/IDT -> карта памяти + framebuffer -> экран -> PMM -> VMM/CR3
        |
    PIC -> PIT -> PCI/xHCI -> COM1 RX + PS/2 -> общий ввод -> консоль -> ожидание в hlt
                               ^           |
                               +-- IRQ0/IRQ1/IRQ4 -> iretq
```

Процессор начинает выполнять код ядра уже в 64-битном режиме на начальных
таблицах страниц Limine. После запуска COM1
ядро устанавливает свои GDT, TSS и IDT. Стек, обработчики исключений
и дальнейшая последовательность запуска принадлежат ядру Malospal OS.
Из памяти с типом `USABLE` распределитель PMM выделяет страницы по 4 КиБ.
Физические адреса не считаются указателями: для доступа к содержимому
используется HHDM. VMM строит собственные таблицы и переключает CR3, сохраняя
смещение HHDM для доступной RAM. Устройство отображений теперь задаёт ядро.
Отдельно сохраняется RW/NX-отображение выбранного framebuffer с кэшированием WC
или UC. Поэтому экран работает и до, и после переключения CR3.
После настройки PIC/PIT и доступных USB/PS/2/COM1 обычное ядро открывает командную консоль.
Ожидание ввода использует `hlt`; таймер продолжает работать без фоновой печати.

## Границы модулей

`arch/x86_64` содержит детали процессора и оборудования. При добавлении другой
архитектуры её код получит соседний каталог с реализацией общих интерфейсов.

`boot/limine.c` переводит ответы загрузчика в структуры ядра. Другие модули
не включают `limine.h`. Карта из максимум 512 областей копируется в `boot_info`,
типы переводятся в собственное перечисление, неизвестные считаются резервом.
Вместе с картой сохраняются смещение HHDM и физический/виртуальный адреса ядра.
Запрос framebuffer даёт необязательный экран: его адрес, размеры, pitch и RGB-маски
копируются в собственный дескриптор. `boot/framebuffer.c` проверяет формат,
переполнения и принадлежность всего диапазона страниц резерву `FRAMEBUFFER`.

`mm/pmm.c` проверяет карту и учитывает только целые страницы внутри доступных
областей. Он исключает физическую страницу 0 и резервирует место под битовую
карту. Биты описывают только доступные области, а не разрывы между ними.
Модуль не зависит от заголовка Limine. [Контракт и тесты PMM](physical-memory.md).

`arch/x86_64/paging.c` реализует интерфейс `vmm.h`: четырёхуровневые таблицы,
страницы 4 КиБ, включение NX/WP и инвалидирование TLB. Таблицы получает из PMM.
Операции отображения ограничены отдельным окном, постоянные области ядра
ими изменить нельзя. Код отображён RX без прямого алиаса, константы R/NX,
данные и стеки RW/NX. По краям четырёх стеков нет отображений.
[Контракт и тесты VMM](virtual-memory.md).

`arch/x86_64/pic.c` настраивает контроллер и подтверждает обслуживание IRQ.
`pit.c` реализует интерфейс `timer.h`: счётчик тиков и ожидание с пробуждением.
`interrupts.c` направляет IRQ0 таймеру, IRQ1 клавиатуре, IRQ4 приёмнику COM1, остальные реальные линии без драйвера
маскирует. Обработчик таймера не печатает сообщения и не выделяет память.
[Контракт и тесты IRQ/таймера](interrupts-timer.md).

`core` задаёт последовательность инициализации. `lib` содержит небольшие общие
функции, которые ядро предоставляет само. Внешней libc и системных вызовов
операционной системы на этом уровне нет.

`arch/x86_64/serial.c` сохраняет принятые байты в фиксированной очереди и сообщает
об ошибках/потерях. `core/line.c` редактирует ограниченную строку без зависимости
от оборудования, `core/console.c` выполняет команды вне обработчика IRQ.
Этот же редактор используется с PS/2-клавиатурой. Переключение источника посреди
строки отменяет её, чтобы не собрать неожиданную команду из разных потоков.
[Контракт и проверки консоли](console.md).

`arch/x86_64/keyboard.c` настраивает i8042 и клавиатуру, принимает сырые байты
в отдельную очередь через IRQ1. `ps2_decode.c` независимо от портов переводит
native set 2 в ASCII, учитывая модификаторы и составные последовательности.
Декодирование и команды выполняются вне IRQ. [Контракт PS/2](keyboard.md).

`usb/xhci.c` получает контроллер от прошивки, выделяет DMA-страницы и перечисляет
USB boot-клавиатуры на root ports. Регистры PCI отображаются отдельным UC/NX
интерфейсом VMM. `usb/hid.c` декодирует отчёты, `core/input.c` объединяет опрос
PS/2, COM1 и USB с разными ID источников. xHCI опрашивается вне IRQ, PIT обеспечивает
пробуждение. [Контракт USB и ограничения](usb-keyboard.md).

`core/debug.c` форматирует сообщения и направляет их в COM1 и `video/screen.c`.
Экранный драйвер рисует растровый шрифт, переносит строки и прокручивает текст
из фиксированного буфера RAM. Динамическая память и чтение VRAM для прокрутки
не нужны. Нет зависимости от протокола Limine или эмулятора. Без COM1 ядро
показывает состояние на экране и принимает PS/2-команды.
[Контракт и проверки экранного вывода](screen.md).

`games/snake_logic.c` и `games/slots_logic.c` содержат правила без драйверов.
Их игровые циклы используют графический режим `video/screen.c`, общий
`games/game_input.c` и PIT. Это синхронные команды ring 0, без процессов и кучи;
IRQ продолжают работать, по выходу восстанавливается консоль. В слот-машине
используется закреплённая PCG basic C, в Змейке адаптированы правила публичного
примера SDL; драйверы и ядро я реализую отдельно.

`tools` работает на компьютере разработчика и никогда не входит в ядро.
Тестовое завершение QEMU включается отдельным флагом компиляции.
Искусственные ошибки из `tests/fault.S` входят только в варианты `fault-*`;
обычный и загрузочный тестовый образы их не содержат.
Исчерпание памяти из `tests/pmm_kernel.c` включено только в образ `memory`.
Проверки таблиц и отказов `tests/vmm_kernel.c` включены только в образ `virtual`.
Проверки IRQ и регистров `tests/timer_kernel.c` и `tests/timer_registers.S`
включены только в образ `timer`. Проверка консоли общается с обычным ядром через
COM1; специальных команд или обходного тестового интерфейса в ядре нет.
Локальные тесты компилируют тот же распределитель, редактор строки
и драйверы PIC/COM1/i8042 с подставными портами, декодер PS/2,
экранный драйвер на массивах пикселей
как обычные программы
компьютера разработчика; их стандартная библиотека не попадает в ядро.

Обработчики исключений пока только сохраняют диагностический снимок и
останавливают процессор. Double fault, NMI и machine check используют
отдельные стеки IST, чтобы не зависеть от доступности основного стека.
Внешние IRQ используют общий вход с сохранением регистров, но возвращаются
через `iretq`. Восстановление после исключений ещё не реализовано.
[Устройство и проверка обработчиков](exceptions.md).

## Следующие этапы

| Этап | Что реализуем | Как подтверждаем результат |
| --- | --- | --- |
| 1. Вход в ядро | Стек, COM1, карта памяти, ISO | Выполнено: обычное и тестовое ядро проходят BIOS/UEFI-проверки |
| 2. Исключения | Свои GDT, TSS, IDT и аварийные стеки | Выполнено: пять исключений проходят BIOS/UEFI-проверки, включая double fault с недоступным стеком |
| 3. Физическая память | Учёт занятых областей, выделение и возврат страниц | Выполнено: проверки искусственных карт и полного исчерпания/возврата памяти в BIOS/UEFI |
| 4. Виртуальная память | Свои таблицы страниц, права доступа, защита стека | Выполнено: переключение CR3, тесты отображений, NX/WP и выхода за край стека в BIOS/UEFI |
| 5. Прерывания и время | Контроллер прерываний, таймер | Выполнено: PIC/PIT, тики, пробуждение, сохранение регистров/флагов и EOI в BIOS/UEFI |
| 6. Ввод и консоль | Последовательный ввод, простые команды | Выполнено: COM1 IRQ4, очередь, редактор строки; теперь 10 команд |
| 7. Экран | Framebuffer, шрифт, переносы и прокрутка | Выполнено: вывод до/после CR3, пиксельные проверки QEMU и запуск VirtualBox |
| 8. Клавиатура | PS/2-ввод в существующий редактор строки | Выполнено: IRQ1, native set 2, US, модификаторы, QEMU BIOS/UEFI и без COM1, команды в VirtualBox BIOS |
| Встроенные игры | Змейка и слот-машина | Выполнено: графический режим, ввод, таймер и возврат в консоль; без пользовательских процессов |
| USB-ввод | PCI, MMIO, xHCI и boot-HID | Ввод и игры без PS/2 и COM1, BIOS/UEFI; физическое оборудование требует проверки |
| 9. Задачи | Контексты выполнения, планировщик | Несколько задач работают без повреждения стеков и регистров |
| 10. Пользовательский режим | Ring 3, системные вызовы, загрузка ELF-программ | Ошибка приложения не повреждает ядро |
| 11. Файлы и хранение | VFS, простой формат файлов, драйвер накопителя | Программа читает данные через стабильный интерфейс ядра |
| 12. Прикладная система | Нужные приложения, сеть и интерфейс | Выполняется конкретная пользовательская задача |

Следующий этап: задачи ядра с отдельными стеками и явным переключением контекста,
после этого планировщик. USB-стек можно расширять хабами, hotplug и другими контроллерами.
До настройки IDT/PIC/PIT нельзя выполнять `sti`. Старые таблицы загрузчика уже
не используются, но его память
пока не возвращается в PMM: повторное использование этих областей будет
отдельным изменением с проверкой оставшихся зависимостей.

## Правила расширения

- Добавляем только необходимую для следующего работающего этапа функциональность.
- Код загрузчика и значения его протокола остаются внутри `boot/`.
- Сведения о памяти сохраняем до освобождения областей загрузчика.
- Физические и виртуальные адреса различаем явно; их совпадение не предполагаем.
- Для операций с устройствами учитываем ошибки и ограничиваем ожидание.
- После изменений загрузки проверяем BIOS и UEFI; после изменений памяти также
  разные объёмы RAM и ошибочные обращения.

## Границы текущего результата

Пока поддерживается один виртуальный процессор, диагностический COM1 и начальная
карта памяти, фатальная обработка исключений и распределитель физических
страниц, собственные таблицы виртуальной памяти, защита стеков, таймер PIC/PIT
и текстовый framebuffer. COM1 необязателен: ввод и экранная консоль работают с PS/2.
PMM/VMM пока не вызываются из прерываний и не поддерживают несколько CPU.
После включения IRQ операции с памятью требуют пары `arch_irq_save()` и
`arch_irq_restore()`. Таймер считает доставленные тики, а не точное реальное время.
Есть простая консоль команд ядра; GUI, многозадачности, дискового драйвера,
запуска внешних программ и полноценной оболочки пока нет.
Загрузчик сторонний; его замена собственным возможна позднее и не обязательна
для разработки своего ядра. Работоспособность на реальном оборудовании пока
не заявляется.
