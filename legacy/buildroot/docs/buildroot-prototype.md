# Архив: прототип MyOS на Buildroot

Это описание предыдущего направления проекта. Текущая работа ведётся над
собственным ядром на C и ассемблере в корневой папке `kernel/`. Актуальная инструкция находится
в [README проекта](../../../README.md). Команды ниже относятся только к старой заготовке.

Собственная компактная система на Linux, собираемая из исходников.
MyOS пока рабочее имя. Первый профиль предназначен для виртуального компьютера
x86-64: текстовая консоль, базовые команды и место для наших программ.

**Статус:** подготовлены исходники проекта и сценарии сборки. Полная сборка
и загрузка ещё не проверены: на исходном Windows-компьютере отсутствует WSL/Linux.
Это заготовка первого прототипа, а не уже готовый загрузочный образ.

Проверено локально: синтаксис всех сценариев, SHA-256 архива, наличие выбранных
параметров в закреплённом Buildroot и отказ проверки загрузки при отсутствии QEMU.
Зависимости параметров и полную сборку ещё должен проверить сам Buildroot под Linux.

## Что означает «с нуля»

Мы сами задаём состав системы, её настройки, службы и приложения.
Buildroot собирает из исходников компилятор, библиотеку musl, ядро Linux и BusyBox.
Готовый дистрибутив внутри нашей системы не используется. Linux и BusyBox при этом
остаются сторонними проектами; собственное ядро мы пока не пишем.

Debian/Ubuntu нужны только как рабочая среда для сборки. Они не являются основой
получившегося образа MyOS.

## Первый запуск на Windows

Нужна WSL2 с Debian либо отдельная виртуальная машина с Debian/Ubuntu.
Ориентир для первой сборки: 30 ГБ свободного места, 8 ГБ оперативной памяти
и доступ в интернет. Фактическое потребление и время зависят от компьютера.

1. В PowerShell от администратора установи WSL с Debian:

   ```powershell
   wsl --install -d Debian
   ```

   Если Windows запросит перезагрузку, выполни её, затем открой Debian и создай
   обычного пользователя. В `wsl --list --verbose` у Debian должна быть версия 2.

2. В терминале Debian скопируй проект в файловую систему Linux:

   ```bash
   mkdir -p ~/src
   git clone https://github.com/malospa1/Malospal-OS.git ~/src/Malospal-OS
   cd ~/src/Malospal-OS/legacy/buildroot
   sudo bash scripts/setup-debian.sh
   ```

   Собирать прямо в `/mnt/c/` и других разделах Windows нельзя: файловая система
   не обеспечивает все необходимые Linux-права и ссылки. После клонирования
   работай в `~/src/Malospal-OS/legacy/buildroot`; папка проекта на Windows
   автоматически с ней не синхронизируется.
   Не копируй старые `output/` между системами. Загруженный архив в `.cache/`
   можно использовать повторно.

3. Собери систему обычным пользователем, без `sudo`:

   ```bash
   bash scripts/build.sh
   ```

   Первая сборка загружает и компилирует инструменты, ядро и программы. При
   прерывании повторный запуск продолжит её. В `output/images/` должны появиться
   `bzImage` и `rootfs.ext4` (ссылка на `rootfs.ext2`, содержащий файловую систему ext4).

4. Запусти автоматическую проверку, затем интерактивную консоль:

   ```bash
   bash scripts/smoke-test.sh
   bash scripts/run.sh
   ```

   В приглашении `myos login:` введи `root`, пароль не требуется. Доступные команды:

   ```sh
   myos-info
   uname -a
   ls /
   free
   poweroff
   ```

QEMU выделяет гостевой системе 256 МБ памяти. Сеть отключена, диски компьютера
не подключаются. Изменения внутри гостя исчезают после выключения благодаря
режиму `-snapshot`. Пароль root пустой только для этой локальной конфигурации
разработки; перед подключением сети или выпуском образа модель доступа надо изменить.

Сейчас QEMU загружает ядро напрямую. Эти файлы ещё нельзя записать на флешку
и загрузить на обычном ПК: загрузчик, разметка и поддержка реального оборудования
будут отдельным этапом.

## Устройство проекта

| Путь | Назначение |
| --- | --- |
| `configs/myos_qemu_x86_64_defconfig` | Состав системы и параметры сборки |
| `board/qemu-x86_64/overlay/` | Файлы, попадающие в корневую файловую систему |
| `package/myos-base/` | Наш первый пакет: `myos-info` и проверка запуска |
| `scripts/` | Подготовка, сборка, запуск и проверка |
| `buildroot.lock` | Версия и SHA-256 архива Buildroot |
| `.cache/` | Загруженный Buildroot, не наши исходники |
| `output/` | Результаты сборки, загруженные исходники пакетов и журналы |
| `docs/architecture.md` | Принятые решения и следующие этапы |

Buildroot закреплён на версии **2025.02.18** из ветки LTS.
Профиль берёт ядро **6.12.109** и конфигурацию виртуального x86-64 компьютера
из этого релиза. Название опции `LATEST_VERSION` относится к закреплённому
Buildroot: произвольное новое ядро из интернета она не выбирает.

## Как развивать систему

Редактирование состава через меню и сохранение минимальной конфигурации:

```bash
bash scripts/build.sh menuconfig
bash scripts/build.sh savedefconfig
bash scripts/build.sh
```

`configure` применяется только к ещё не настроенной папке `output/`.
Обычная сборка не перезаписывает изменения, сделанные в меню.
Изменения файлов `myos-base/src/` подхватываются при следующей сборке.
Новые программы оформляем отдельными каталогами в `package/`; их `Config.in`
нужно подключать в корневом `Config.in`.

При удалении пакетов/файлов из overlay или изменении компилятора, архитектуры,
библиотеки C нужна чистая сборка: сохрани конфигурацию, переименуй `output/`
в резервный каталог и снова запусти сборку. Обычная повторная сборка Buildroot
не гарантирует удаления старых файлов из готовой системы.

Проверка `smoke-test.sh` ждёт не более 120 секунд. Успех означает загрузку Linux,
выполнение `myos-info`, наличие `/sys` и `/dev/console` и завершение QEMU после
выключения гостя. Она не проверяет вход в консоль, сеть или реальное оборудование.
Журнал сохраняется в `output/smoke.log`.

Перед распространением сборки собери сведения о лицензиях сторонних компонентов:

```bash
bash scripts/build.sh legal-info
```

Это вспомогательный отчёт, а не автоматическое выполнение всех лицензионных
обязательств. Лицензию нашего собственного кода ещё предстоит выбрать.
